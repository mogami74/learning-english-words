# 開発ルール・指示書

## 📋 コード管理ルール

### 🔄 Git運用ルール

#### 1. コミット後の必須作業 ⚠️ **最重要ルール**
```
git push → 開発ログ更新 (必須)
```

**厳格な手順**:
1. `git add .`
2. `git commit -m "詳細なコミットメッセージ"`
3. `git push origin develop`
4. **🚨 必須**: `DEVELOPMENT_LOG.md` を**即座に**更新
   - 実装した機能の詳細記録
   - 技術的課題と解決策
   - 作業時間と進捗状況
   - 次回の改善点
5. 開発ログ更新後、再度コミット・プッシュ

**例外なし**: git pushを行った場合、必ず開発ログを更新する
**忘れ防止**: `.instructions/git-checklist.md` を参照

#### 2. コミットメッセージ規約
```
feat: 新機能追加
fix: バグ修正
docs: ドキュメント更新
style: コードスタイル調整
refactor: リファクタリング
test: テスト追加・修正
chore: その他の作業
```

#### 3. 開発ログ記録項目
- **時間**: 作業開始・終了時刻
- **内容**: 実装機能の詳細
- **技術**: 使用した技術・ライブラリ
- **課題**: 発生した問題と解決方法
- **統計**: コード行数・ファイル数等
- **次回**: 今後の改善予定

## 🎯 機能開発ルール

### 📱 UI/UX設計原則
1. **ファーストビュー重視**: 重要な機能は上部に配置
2. **レスポンシブ必須**: PC・タブレット・モバイル対応
3. **アクセシビリティ**: ボタンサイズ・コントラスト配慮
4. **ユーザビリティ**: 直感的な操作フロー

### 🏗️ アーキテクチャ原則
1. **モジュール化**: 再利用可能なコンポーネント設計
2. **型安全性**: TypeScriptの型定義を活用
3. **エラーハンドリング**: 適切な例外処理と縮退運転
4. **データ永続化**: localStorage + ファイル保存の二重化

### 🔧 コード品質基準
1. **命名規則**: 明確で意味のある変数・関数名
2. **コメント**: 複雑なロジックには日本語コメント
3. **関数分割**: 単一責任の原則に従った関数設計
4. **パフォーマンス**: 不要な再レンダリング・再計算の回避

## 📚 学習システム仕様

### 🎲 難易度システム
- **範囲**: -1（非表示）〜 10（最高難易度）
- **初期値**: 1（標準）
- **調整方法**: 
  - 「覚えた」ボタン: -1
  - 手動調整: ±1ボタン
  - 一括調整: 全単語+1

### 🎯 重み付きランダム選択
```typescript
const weight = Math.max(1, word.difficulty);
// difficulty値に比例した出現確率
```

### 💾 データ管理
1. **メモリ**: リアルタイム操作
2. **localStorage**: ブラウザ保存（バックアップ）
3. **ファイル**: Express.js API経由の永続化

## 🛠️ 開発環境管理

### 📦 必要なサーバー
1. **Express.js**: ポート3001（API）
2. **Webpack Dev**: ポート8082（フロントエンド）

### 🚀 起動コマンド
```bash
# サーバー起動
npm run server

# 開発サーバー起動  
npm run webpack:dev

# 両方同時起動
npm run start:full
```

```bash
# 開発ビルド
npx webpack --mode development

# 本番ビルド
npx webpack --mode production
```

## ⚠️ 重要な注意事項

### 🔒 データ安全性
- 一括操作前は必ず確認ダイアログ表示
- 元に戻せない操作は明確に警告
- エラー時の適切な縮退運転

### 🎨 UI一貫性
- カラーパレット: 青系グラデーション（#667eea 〜 #764ba2）
- フォント: 'Segoe UI', Tahoma, Geneva, Verdana
- ボタン: 10px角丸、ホバーエフェクト必須

### 📱 レスポンシブ対応
- PC: 1200px幅想定
- タブレット: 768px〜1199px
- モバイル: 〜767px
