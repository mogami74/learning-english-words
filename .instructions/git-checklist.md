# Git Push チェックリスト

## 🚨 **最重要**: プッシュ後の開発ログ更新

**⚠️ 例外なき必須作業**: `git push` 実行後は **必ず** `DEVELOPMENT_LOG.md` を更新する

```
git push → 開発ログ更新 → 再コミット・プッシュ
```

---

## ✅ プッシュ前チェック項目

### 🔍 コード品質確認
- [ ] TypeScriptエラーなし
- [ ] Webpackビルド成功
- [ ] ブラウザでの動作確認完了
- [ ] コンソールエラーなし

### 📝 コミット準備
- [ ] 変更ファイルの確認（`git status`）
- [ ] 意味のあるコミットメッセージ作成
- [ ] コミット対象の精査（不要ファイル除外）

### 🚀 プッシュ実行
```bash
git add .
git status  # 最終確認
git commit -m "feat: [機能概要] - [詳細説明]"
git push origin develop
```

## 📋 プッシュ後の必須作業 🚨 **絶対に忘れてはいけない**

### 🔴 第一優先: 開発ログ更新
**重要**: この作業なしには、git pushは完了していない

### 🆔 コミット情報取得
```bash
git log --oneline -3  # 最新3件のコミット確認
```

### 📚 開発ログ更新
`DEVELOPMENT_LOG.md` に以下を記録：

#### 必須項目
1. **日時**: 作業日時
2. **作業内容**: 実装した機能・修正内容
3. **コミットハッシュ**: git logで確認した値
4. **技術詳細**: 使用した技術・ライブラリ
5. **課題解決**: 発生した問題と解決方法

#### 統計情報
- [ ] 変更ファイル数
- [ ] 追加・削除行数
- [ ] 新規機能数
- [ ] 修正バグ数

#### 記録テンプレート
```markdown
## YYYY年MM月DD日 - [作業タイトル]

### [時刻] - [作業内容]
**コミット**: `[ハッシュ]`

[作業番号]. **[機能名]**
   - [詳細説明]
   - 技術: [使用技術]
   - 課題: [解決した問題]
   - 効果: [改善効果]
```

## ⚠️ 緊急時対応

### 🚨 問題発生時
1. **即座に調査**: コンソールエラー・ネットワークエラー確認
2. **ロールバック検討**: 前回正常コミットへの復帰
3. **チームへ報告**: 問題内容と影響範囲の共有

### 🔄 ロールバック手順
```bash
git log --oneline -10  # 履歴確認
git reset --hard [正常なコミットハッシュ]
git push --force-with-lease origin develop
```

### 📞 エスカレーション基準
- 本番環境に影響する問題
- データ損失の可能性
- セキュリティに関する問題
- 1時間以内に解決できない問題
